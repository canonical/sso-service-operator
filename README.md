## Description

Python Operator for the Canonical Identity Platform SSO Service

## Network

The charm opens the ports `8080` (HTTP) and `50051` (gRPC) on the application's Kubernetes
Service and restricts neither of them.

**Important:** the sign-in service on `50051` is served **without a token**, because the login
UI calls it before a user has one. The deployment has to restrict that port to the login UI.

The `public-route` gateway has to be the one the login UI is served on, because the login UI
reads a cookie that the service sets. The charm does not check it.

## Envelope key

The key that encrypts the identity providers' client secrets in the database is kept in a Juju
secret of the application, generated by the leader in its first hook.

**Important:** back up the database and the key together. A database restored without its key
has no readable client secrets.

```bash
juju run sso-service/leader get-envelope-key
```

To restore into a new deployment, put the key in a Juju secret under the entry `key`, deploy the
application with `initial_envelope_key_secret_id` set to the secret's id, then grant the secret
to the application.
